## 11. 教訓

### 良かった点

- **設計 → 計画 → 実装** の 4 段順守（前書 04）が機能した
- **共通テンプレ**（章立て統一）で穴埋め式に書けた
- **Read で原典確認 → 抜粋** で精度を保った
- **索引（25）を最後に書く** ことで全体構造が整理された
- **計画書（11）を Draft で書いて承認を待った** ことで、ユーザーが連番形式に修正でき、無駄手戻りなし

### 改善余地

- 計画段階の **行数見積もり** に ±20% 程度の誤差。これは経験則として 07 に追加できる
- D11 / D12 / D13 を 1 つに統合する案もあった（中規模文書）。次回検討
- Gemini CLI と分担して **設計書を別 AI に書かせる** 選択肢もあった（前書 16）。今回は単独完走を優先

### 再現する人へ

「**26 文書 / ~10,000 行 / 1 セッション**」のドキュメントシリーズは、以下があれば再現可能:

1. **基盤文書（01〜09 相当）** を先に書いて全体像を共有
2. **候補リスト（10）** で網羅的に未カバー実例を洗い出す
3. **計画書（11）** で D1〜D15 に分解、Draft 承認を取る
4. **共通テンプレ** で章立て統一
5. **コード抜粋は実体から Read** して書く
6. **索引（25）** で読む順番を提示
7. **完了レポート（26）** で品質保証

このリポジトリの **「設計 → 計画 → 実装 → テスト + 文書」** ワークフローが、文書シリーズ作成にもそのまま応用できることが実証された。
